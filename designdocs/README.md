# Design documents

Longer-form design and investigation notes that outlive a single pull request.

These are **not** user documentation and **not** a specification of current behaviour. Each
document records a proposed change: why it came up, what the investigation turned up, what the
design would be, and what the risks are. A document living here does not mean the work is
scheduled, approved, or started — check the `Status:` line at the top.

Keep the `Status:` line current. When a design is implemented, say so and link the PRs; when it is
abandoned, say why rather than deleting the file — the investigation is usually the valuable part.
